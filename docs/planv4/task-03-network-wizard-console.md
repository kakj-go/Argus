## 保留的领域约束

- 主机模式目录固定为：①双向可达、②只进不出、⑤只出不进/自助安装、标准堡垒机成员、受限端口堡垒机成员。
- 堡垒机模式目录固定为：A 手动命令安装、B 平台 SSH 代安装、C 平台 SSH 代安装 + 控制隧道。
- 场景卡只帮助用户表达网络事实，ConnectionTest、冻结计划和服务端约束才是提交事实来源。
- 技术标识（如 `direct_ssh`、`direct_argus`、`executor_tunnel`）不得作为普通用户完成选择的必要知识；可放入展开的技术详情。
- 一次性命令不进入 URL、localStorage、Query Cache 或普通资源 DTO，关闭结果页后清除明文。

## 交互约束

- 使用现有 `Dialog`、`Wizard`、`ScenarioCard` 等共享原语，不建立业务应用私有的平行组件库。
- 第一步只允许出现模式选择和模式解释，不得渲染主机名、地址、凭据等表单字段。
- 第二步只显示已选模式摘要和对应表单，不保留可直接切换的完整模式列表。
- 第三步按模式动态显示“测试连接与确认”或“确认并生成命令”；步骤条必须与真实状态一致。
- 输入字段必须位于真实 `<form>` 中，支持 Enter 提交、原生语义、错误关联和键盘焦点恢复。
- body 可以滚动，但不得同时依赖两个长滚动区完成一个步骤；桌面常用视口内应看见当前步骤的主操作。
